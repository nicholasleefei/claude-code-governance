# 2026-09-06-14 · CLI/MCP 跑通经验沉淀 · Z-13 定案

## 议题背景

用户提出：CLI/MCP 工具跑通一次后，下次复用往往要重新踩坑，建议把跑通经验记下来，避免重复劳动。

## 讨论过程

**触发机制确认：**
- 用户倾向「用户主动说跑通才记」，不强制自动记录
- 理由：自动触发时机难判断，容易噪音；等用户主动确认更可靠

**专档位置：**
- `E:\04-cli\跑通纪要\` 下按 `CLI-XXX\` 分夹
- `index.html` 作总索引
- 不入台账主表（台账主表只记"有没有这个工具"，专档记"怎么用通"）

**内容结构（五项）：**
1. 工具名称 + CLI编号
2. 跑通日期（用户确认为准）
3. 关键步骤（与官方文档不同处 / 踩过的坑）
4. 遇到的坑 / bug（报错信息 + 解决方式）
5. 注意事项（版本约束 / 环境要求）

**防噪音机制（5条）：**
1. 工具执行报错退出 → 不记录
2. 部分成功有未解决副作用 → 记为"有已知问题"而非"跑通"
3. 同一CLI重复跑通 → 只更新"最近确认时间"，不重复写同类细节
4. 口头确认但实际有未解决报错 → 不记录
5. 新坑追加、有重复合并，不覆盖已有记录

**更新机制：** 重复跑通只更新确认时间；有新坑点追加写入，不覆盖。

**生效方式：** 入专档即生效（软规则/记忆型经验），不强制走 §4 三通道。

## 决议
