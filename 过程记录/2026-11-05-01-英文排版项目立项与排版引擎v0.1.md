## 3. 关键故障与坑（都写进项目文档）

1. **权限分类器宕机**（2026-11-05 全天）：非只读工具间歇性被拒，只读工具恒可用。
   写文件靠"小探测 → 成功就批量发"的节奏推进；期间一度靠 `Bash` 只读命令（`python --version`）确认过可用，
   但**没有借 Bash 绕开 Write 的分类检查**（那等于规避安全机制）。
2. **`NoDefaultCurrentDirectoryInExePath=1`**（本机环境变量）：cmd.exe 因此**不在当前目录找可执行文件**，
   在 Git Bash 里跑 `typo.cmd` 必须写 `.\typo.cmd`；资源管理器双击与 cmd 提示符内不受影响。
   另：`.cmd` 必须 **CRLF**，且批处理文件内**别写中文**（cmd 按系统代码页读，非 ASCII 注释会搞乱行解析）。
3. **`python -I`（隔离模式）会把脚本目录移出 `sys.path`**：扫描器这类"要 import 自己包"的脚本
   不能直接 `-I` 跑；改为脚本内自行 `sys.path.insert`。
4. **PANOSE 的 Serif Style 语义**：我最初把 `bSerifStyle >= 2` 当衬线，
   结果 **`11 = Normal Sans`（无衬线）也被判成衬线**——LINE Seed Sans / D-DIN-PRO 全错。
   正确表：衬线值 {2,5,6,7,8,9,10}、无衬线值 {1,11,12}；`0` 表示"无判定值"应返回**判不出**而不是瞎猜。
   修正后衬线判定落在 Mincho/明朝 系（真衬线）与 Sans 系（真无衬线）上。
5. **不要拿 CJK 字体当英文字体**：光看 `latin_ok` 不够——补了 `latin_coverage`
   （代表性英文句子的字符覆盖率），配对时要求 ≥ 0.98，挡掉只带基础拉丁的 CJK 字体。
6. **模数级数步数表必须单调**：`body-lg` 与 `heading` 同占 0 步会让级数序列非单调（body-lg 反而比 title 大）。
   现约定 `base_px = 正文字号`（body 落在 0 步），步数从 display-2xl=8 单调降到 caption=-2。
7. **`--json` 位置坑**：argparse 的顶层 flag 必须在子命令**前**——对 agent 是常见错误。
   改为自扫 argv + `parse_known_args`，子命令前后皆可。
8. **控制台编码**：Windows 控制台默认 GBK，中文输出花屏 → `stream.reconfigure(encoding="utf-8")`，
   CLI 与 MCP 服务端都要加（后者尤其重要：MCP 报文必须 UTF-8）。

## 4. 定案：引擎 v0.1 的硬规矩

1. **度量优先**：文本宽度用真实 advance width 算，不靠字符数估算。
   快速路径（度量法）**不含 kerning 与连字**，偏小 0.3%–1%，用于断行预算安全；精确路径走 Pillow 栅格化或 HarfBuzz 整形。
2. **每条建议可解释**：返回值带 `rule_id`、人话理由、`provenance.verified`。
   **未核实的数值一律 `verified=false`**，agent 必须如实转述，不得说成"规范规定"。
3. **不硬猜**：衬线判不出返回 `null`；配对引擎把"判不出"当中性（0.7 分），既不加分也不扣分。
4. **不误伤**：lint 前先遮罩 URL / 邮箱 / 行内代码 / HTML 标签。
5. **只搬度量不搬字体**：8.4 GB 字体本体留在 #31 free-font 原处，本项目只存路径与度量（1.5 MB）。
6. **零依赖 MCP**：自实现 MCP stdio（按行分隔的 JSON-RPC 2.0），免装包、免联网即可注册。

## 6. 研究线现状（诚实边界）

**已核实**：断词与断行——`hyphenate-limit-chars` 默认 **5 / 2 / 2**（词长 / 连字符前 / 后）、
`hyphens: none|manual|auto` 初始 manual、U+00AD 软连字符优先于自动断点、U+2010 硬连字符、
`<wbr>` 不加连字符、自动断词需 `lang` + 词典、`word-break: break-all` / `line-break: anywhere` 禁用断词、

MDN hyphenate-limit-chars、W3C css-text-4 §6.3.4。
