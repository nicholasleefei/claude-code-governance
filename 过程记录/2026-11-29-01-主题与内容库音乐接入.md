## 四、音乐创作（本机 YuE2-3B）

- 环境：`E:\ai-env\py-yue2-313`（torch 2.11.0+cu128 / transformers 4.57.6 / yue2-infer 0.1.5 / soundfile）；模型 `E:\01-model\M-020-YuE2-3B\{YuE2-3B,YuE2-Vae}`（6.8GB + 506MB）。登记 `local_models.yue2-3b`：`backend=script`、`status=ready`、`load_mb=14000`。
- 链路：`/create/music` → `POST /creation/tasks (kind=music)` → `creation_ai` 拼风格 → `_local_run('yue2-3b')` → `script_worker.run_yue2`（跑官方 `yue2` CLI）→ ffmpeg 转 mp3 → `creation_assets`（我的创作）。
- CLI：`sbcli creation models --capability music`、`sbcli creation music ... --wait`、`sbcli creation task/tasks`；助手提示词已补。
- 实测：任务 200，86.9→88.56 秒 48kHz 立体声，mp3 1.9MB，资产 id 156；约 60–75 秒出片。
- **坑（重要）**：
  1. 进程内调 `YuE2Pipeline` 在本机 VAE 解码阶段会崩（`0xC0000005`），改走官方 CLI 子进程。
  2. 根因之一是 Windows **提交内存**不足（模型解码前要搬 CPU）：可用提交 4.8GB 必崩、21GB 稳定；适配器现在预检提交内存 ≥12GB，并先请求 ComfyUI `/free`。
  3. `--quantization fp8` 显存够但慢约 13 倍（95 → 7 tokens/s），不用。
  4. HF 缓存必须 `HF_HOME=E:\01-model\_cache\huggingface`（Z-02），适配器里已固定。
  5. 一次只跑一条；并发会触发内存问题。
