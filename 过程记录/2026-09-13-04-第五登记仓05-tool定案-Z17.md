# 2026-09-13-04 · 第五登记仓 05-tool 定案 · Z-17

## 议题背景

本场接续 2026-09-13-03。当日早些时候秘书长派只读侦察书记对 E 盘根目录做了一次盘点（用户提出"最近工作文件里出现一些没法判断的文件夹，E 盘是总体工作文件夹"），结论是：四登记仓（01-model / 02-skill / 03-mcp / 04-cli）之外，本机还散落一类无台账归宿的东西——VS Build Tools（编译器）、cmake/COLMAP/ffmpeg（构建链/领域软件）、ComfyUI/Ollama（本地应用/服务）、Python venv（运行环境），体量大、部分被项目强依赖，却无登记、无巡检覆盖。

盘点汇报后，用户主动提出：「要不进行一个 tool 文件夹的建立，用于存记录非四大模型的工具。区别于 cli，和 mcp 以及模型。」秘书长据此立候选 T-14，并就三个设计点请用户拍板。

**与会：** 用户（拍板）、顶层主会话（＝秘书长，主持/拟稿/派单）、小希·书记长（领衔编排）、四名并行书记子 Agent（台账／总则＋镜像／执行／草案＋纪要分工）、一名对抗性核验员。

## 讨论过程

秘书长先摆三条事实：① `E:\tools` 已物理存在（1.7G，cmake/COLMAP/ffmpeg，9/8 为 3DGS 建）；② BuildTools/venv/ComfyUI 等大件不宜物理搬迁（写注册表、路径硬编码、正挂载模型），天然该走登记制；③ cmake/ffmpeg 与 04-cli 存在灰区，需仲裁原则。随后以三问请用户逐项拍板，用户选定：

1. **形态 ＝ 登记制 ＋ 便携落点（推荐项）。** `E:\05-tool\` 只放 index.html 总台账、实体不强搬不联接；既有 `E:\tools` 定性为「绿色便携工具统一落点」（解压即用者入此）；安装版/本地应用/虚拟环境一律留原位、台账只记路径。
2. **收录四类全收：** 构建工具链、命令行领域软件、本地应用/服务、运行环境。
3. **编号命名 ＝ 05-tool。**

另有两点由秘书长建议、用户一句「通过」一并采纳：

4. **工具编号前缀用 `TOOL-001`**（不用 `T-001`），以免与草案候选号 T-XX 同字母混淆；TOOL 号与 M-/S-/MCP-/CLI- 相互独立、只增不复用。
5. **Ollama 首批挂「待核实」不占号**（安装形态/路径未核实）；vcpkg 两处（约 16G/1.3G）主从未定，同样待核实。

**与 04-cli 的仲裁原则（定案）：** 按"用途归属"切——服务 Claude/agent 工具生态、被 agent 直接当工具调用的命令行进 04-cli；服务具体项目构建/领域处理的进 05-tool。同一可执行不重复登记，跨类编号互链（沿用 Z-04）。
