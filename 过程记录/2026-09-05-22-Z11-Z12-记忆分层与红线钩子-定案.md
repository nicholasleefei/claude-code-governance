## 三、落地执行（入 E-11/E-12，不入正文）

- E-11（记忆分层）：四层定位与读写纪律——CLAUDE.md 每会话全量加载、只承载稳定规则/红线（单向同步勿塞琐事）；memory 每会话仅注入 MEMORY.md 索引头、正文文件按需读取、一条一文件，MEMORY.md 只放一行条目索引；纪要（Z-08）只增不改记正式过程；活档由助理人格（如 小莫）维护进行态。写读纪律——一条事实只落一层、不两处重复；能从代码/git 推得者不写；能立成规则的进 总则/CLAUDE.md、属个人或项目语境的进 memory、属正式过程的进 纪要。索引护理——MEMORY.md 一行一条控总量、Claude 会话内可说"记住…"触发自写、管理用 /memory 定期清理，防超限"无声失忆"。红线——memory 与纪要均明文落盘，遵守 Z-09 不落凭据；涉密强度要求高时可整体关闭 auto memory。
- E-12（红线钩子）：生效位——用户级 ~/.claude/settings.json 管所有会话、项目级 .claude/settings.json 管单项目、多级合并，先 Read 现有 settings 再合并勿覆盖。拦点与事件——PreToolUse 在权限检查前执行、能穿透 bypassPermissions、只能收紧不能放松；对 Z-09 的拦点＝写文件工具（Write|Edit|MultiEdit）写前扫内容命中即拦，对"密提交"的拦点＝Bash 命中 git commit* 时先 git diff --cached 扫一遍。退出码语义与 fail-closed——0＝放行、2＝拦截、其它非零（含 1）＝仅警告；钩子超时/异常默认放行（fail-open），红线守卫必须 catch 一切异常后回 exit 2，宁错拦不漏放。双保险——Code hook 只约束 Claude 会话内动作，含人手在内的所有提交由 git pre-commit 再拦一道。定位与真锁——hook 是配置文件、可被会话内诱导改动，是防线非锁；个人机真锁＝系统只读 ACL 锁 settings 与钩子脚本，企业/团队另有 managed-settings 通道。上钩纪律——先小范围试点确认不误拦日常再放开全局；每次装/改钩子登记（装什么/何时/管什么/在哪级）；Claude 升级后复核仍生效。
