# 过程记录 2026-10-27-02 · product-poster-motion 路线 D 攻坚：笔触表面为何学不到（尺度假设成立）

> **Z-08「只增不改」纪要** · 编号 2026-10-27-02 · 主题：上一纪要（纯噪点事故）收口后继续攻路线 D → 诊断"LoRA 学会了构图却没学会笔触" → 定位为**训练尺度错配** → 改造训练管线并重训验证 → 顺带修掉**评分器自身缺陷**与**两处库内静默错位**。

---

## 0. 一句话

路线 D 的簇 LoRA 能迁构图语言与配色、迁不了笔触表面；诊断发现不是欠训而是**尺度错配**（老训练代码把竖构图 cover 裁成方形），改为**原生分辨率 + 保构图**重训后增益翻倍且不再随分辨率消失；过程中另发现评分器 `_ratio_score` 有缺陷使"自比恒为 1.000"失效，以及 caption 键错位与清洗后 hash 错位两处静默不一致。

---

## 1. 诊断：把"表面学不到"拆成可测的因子

同 seed 123 / 同内容 / 28 步 / CFG 3.5 / 内容「a winding stone garden path through the flower meadow」，
换生成分辨率、换 LoRA 强度，各带基模对照（评分器 v7）：

| 生成分辨率 | 旧 LoRA | 基模 | 增益 |
|---|---|---|---|
| 512×512 | 0.649 | 0.600 | **+0.049** |
| 768×1344 | 0.672 | 0.659 | +0.013 |
| 1024×1024 | 0.672 | 0.675 | **−0.003（无增益）** |

| LoRA 强度 | 簇均分 |
|---|---|
| scale 0.6 | 0.675 |
| scale 1.0 | 0.672 |
| scale 1.4 | 0.647 |

**读法**：
- 增益**随生成分辨率放大而消失** → 不是"训得不够"，是**尺度**问题；
- 调强度没用（0.6 反而最好）→ 排除"欠训/欠强"这一路假设。

**回查训练代码找到病根**：`load_image` 是 **cover 缩放 + 居中裁切**——把 736×1308 的竖构图
裁成 512×512 方形。**构图关系与笔触相对尺度在训练阶段就被裁掉了**，
而"学构图语言"恰恰是簇 LoRA 的立身之本。全库尺寸统计：**2/3 是宽高比 ≈0.56 的竖构图**，
方形裁剪对它们都是重伤。

## 2. 改造与验证：假设成立

- `load_image` 新增 `fit`：`stretch`（直接缩放，保构图与尺度，形变约 1.4% 可忽略）/
  `cover`（旧法，留作对照）/ `pad`（等比补边，会教模型画黑边）。
- 训练器新增 `--resolution WxH`、`--fit`、`--out-name`。
- 用**生成端原生 768×1344 + stretch** 重训 300 步（**与旧 LoRA 同步数**，唯一差别是分辨率与 fit → 干净 A/B）。
  12.8 分钟、16.6GB 显存、探针 cos 0.674→0.683。产物 `lora/cluster_densefloral_768/`。

| 生成分辨率 | 旧 LoRA（512 cover） | **新 LoRA（768×1344 stretch）** | 基模 |
|---|---|---|---|
| 512×512 | **+0.049** | +0.021 | 0.600 |
| 768×1344 | +0.013 | **+0.032** | 0.659 |
| 1024×1024 | **−0.003（消失）** | **+0.007（转正）** | 0.675 |

**结论**：训练分辨率匹配的那一档增益翻了一倍多；效果不再随分辨率放大而消失；
旧 LoRA 在 512 的优势随之缩水——正合"那本来就是 512 尺度效应"的解释。**假设成立。**

**仍然没解决**：厚涂的**笔触表面**还是没学到（出图像照片不像油画）。
未验证的下一步方向：① caption 只写内容、没写"这是绘画"，FLUX 的照片先验压过 LoRA；
② 300 步 / rank 16 对高频质感的刻画能力不足。

## 3. 顺带修掉的三件事

### 3.1 评分器自身缺陷（`dna_score.py` → 版本 `v7_2026-10-27`）

`_ratio_score` 的「ref 极小」分支写成 `1 - gen/0.05`（离 **0** 的距离），
而不是 `1 - |gen-ref|/0.05`（离 ref 的距离）→ `stroke_coherence` 0.016 对 0.016
这种**完全一致**也只得 0.68，**「自比恒为 1.000」这条不变式被破坏**，
凡是 ref<0.02 的维度全被无端扣分。已修 + 加版本号（**改公式必须改版本号，旧分数一律作废**）。
修后校准：**51 张参考图自比全部恒为 1.000**。

**教训**：当尺子用的测量工具，先拿"自己跟自己比"做校准；工具改公式就是换尺子。

### 3.2 caption 键错位（静默）

`caption_refs.py` 原按**文件名**命名 caption，而 DNA 是**内容哈希** →
留下孤儿 `81dM+Beq.txt`，而对应图 `81dM+BeqW1L...jpg`（DNA 哈希 `0eca49fa`）**反而没有 caption**
→ 训练时静默退化成 "a painting"。已改为按 DNA 哈希命名，补齐至 51/51。

### 3.3 清洗后 hash 错位（静默）

`mask_reference.py --reextract` 用清洗图重提 DNA 时，`extract()` 把 **`hash` 字段算成了清洗图的哈希**
（文件名仍是原哈希）→ 全库按 hash 建的索引（caption 键 / clean_refs 键 / 网页数据）集体错位。
已修（hash 与 source 一律留在原图上）。

### 3.4 新增库体检 `scripts/check_library.py`

校验 DNA 文件名 == JSON 的 hash、source 存在且唯一、参考图 ↔ DNA 一一对应、caption 齐备、
`scene_scale` 在、`_method_version` 一致、有 clean_refs 则须有 `_mask_note`。
**上面 3.2 / 3.3 两次静默错位正是它该抓的**。现体检：51 DNA / 51 参考图 / 51 caption，全一致。

### 3.5 带文字的参考图

`参考/下载 (1).png` 是**带手写文字的贺卡插画**。新增 `scripts/mask_reference.py`：
复用 `dna_generate.clean_reference` 的逐列中值插值抹字（已验证），清洗版存 `lora_data/clean_refs/`；
`flux_lora_train.find_ref` 与 `dna_score` 的基准图**都优先用清洗版**（基准必须与 DNA 同源）；
`caption_refs.py` 也改用清洗版描述（VLM 输出："A cluster of daisies with white petals and yellow
centers extends diagonally across the frame against a clear blue sky."——没提文字）。
