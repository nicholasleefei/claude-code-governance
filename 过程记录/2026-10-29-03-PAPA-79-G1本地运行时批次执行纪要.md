## 2. 坑一：Node 的 `fetch` 不认 `HTTPS_PROXY`（会复发）

**现象**：`qmd pull` 跑了 8 分钟，模型目录 0 字节，**没有任何报错**，进程只是挂着。

**根因**：本机 HuggingFace **仅经代理可达**——`curl https://huggingface.co/` 直连返回 `000`、经代理返回 `200`。而 Node 24 的全局 `fetch` 默认**直连**，不读 `HTTPS_PROXY`；只有显式 `NODE_USE_ENV_PROXY=1` 才会走代理环境变量。

**验证**：`NODE_USE_ENV_PROXY=1 node -e "fetch('https://huggingface.co/api/models?limit=1')..."` → `status 200`；不开 → `fetch failed`。

**处置**：把 `NODE_USE_ENV_PROXY=1` 固化进启动器 `E:\tools\qmd\qmd.cmd`（与 `XDG_CACHE_HOME` 一起）。**凡是本机用 Node 直连 HuggingFace/npm 的工具，都会踩这个坑。**

**顺带**：官方建议的 `HF_ENDPOINT=https://hf-mirror.com` 实测**更慢**（86 KB/s vs 直连代理 435 KB/s），本机不要切镜像。

## 3. 坑二：写 .cmd 启动器时 shell + Python 双层转义把路径吃成控制字符

**现象**：qmd 报 `ENOENT: mkdir 'E:\tools\qmd\<SOH>-model\_cache\qmd\models'`——`E:\01-model` 里的 `\01` 被当成八进制转义变成了 SOH（`\x01`）。

**根因**：脚本是 `bash -c "python -c \"...\""`，bash 双引号先把 `\\` 折成 `\`，Python 再把 `\01` 解析成八进制转义。两层各折一次，`E:\01-model` 就废了。

**处置**：`.cmd` 一律**用 Write 工具直接写文件**（不经 shell 二次转义），再用 Python 把换行统一成 CRLF。**含 `E:\01-model`、`E:\tools` 这类以数字开头的路径段时，一律走这条。**
