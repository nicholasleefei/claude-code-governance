## 一、动因回顾（T-06 建仓引出 → 拆 T-10）

- T-06（E:\claude code总则 入 git 版本库、主仓公开托管）落定后，「规则已可公开读取」成为事实，自然引出下一步：**装到其它电脑上用**。

## 二、已定方向

- **主仓权威**：主控机＝本机（规则主仓所在，唯一写者）；改规则只认主仓。
- **使用机只读**：其它电脑对主仓匿名 clone/pull，永不 push。
- **镜像按机编译**：各使用机按装机提示词把主仓总则编译成本机 CLAUDE.md——通用规则照抄，本机存储/落点规则按该机实际，不照抄主仓盘符。
- **工具不镜像、按需装**：skill/model/MCP/CLI 不随仓镜像，各机按需安装、按需登记。

## 三、关键实现点

- 公开仓（github.com/nicholasleefei/claude-code-governance）＋ 匿名 https clone = 使用机**无凭据即无写权限**，天然物理只读——省去 deploy key / 凭据分发，从机制上杜绝使用机误 push。

## 四、Z-10 结论板全文（定案即生效，字面不改）

「Z-10 · 治理体系多机部署（主仓权威 · 使用机只读）：体系分层——主控机为本机（规则主仓所在，唯一写者）；使用机为其它电脑（只读）。主仓公开托管于 github.com/nicholasleefei/claude-code-governance，规则修订只认主仓；使用机以匿名方式 git clone / pull（公开仓无凭据即无写权限），永不 push。各使用机按装机提示词从主仓拉取并编译本机 CLAUDE.md 镜像：通用规则照抄，本机存储/落点规则按该机实际，不照抄主仓盘符；skill/model/MCP/CLI 不随仓镜像，各机按需安装、按需登记。」

## 五、E-10 要点

- 部署模型：主控机＝本机（唯一写者，P-8 收尾即密提交 push）；使用机＝其它电脑（匿名 https clone 公开仓，无凭据即无写权限，物理只读，永不 commit/push）。
- 装机五步（见装机提示词 v2 TXT）：第〇步自我核对 → 摸清本机三事 → 编译本机 CLAUDE.md（通用照抄 + 存储按机盘符）→ 按需装工具菜单 → 更新与收尾（git pull、凭据纪律、新会话生效）。
- 规则更新＝使用机 git pull + 必要时重编译镜像；改规则只回主控机。
- 备注：讨论可在任意机进行，落定案只在主控机。
- 通俗解释：主仓＝宪法正本存总部（主控机），唯一能改字；使用机＝分部人手一册复印件，只等总部发新版（git pull），分部装什么工具自己定。
