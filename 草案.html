T-11 · 记忆分层 · 各司其职不打架拟定 → Z-11

  • 范围本机 Claude Code 的记忆层：用户级 CLAUDE.md（总则镜像）、auto memory（~/.claude/projects/…/memory）、过程记录 纪要（Z-08）、助理活档。
  • 分层CLAUDE.md＝稳定规则/红线镜像，只放总则定稿、单向同步、不塞琐事；memory＝事实/偏好/纠偏，一条事实一个文件，MEMORY.md 只放一行条目索引；纪要＝只增不改的正式过程（Z-08）；活档＝助理人格维护的进行态。
  • 纪律一条事实只落一层，不两处重复（重复＝双份常驻 token＋可能冲突）；能从代码/git 推得者不写；能立成规则的进 总则/CLAUDE.md，属个人或项目语境的进 memory，属正式过程的进 纪要。
  • 索引护理MEMORY.md 每会话仅注入索引头，约 200 行/25KB 后静默截断、超限即"无声失忆"：控制条目数，定期 /memory 清理。
  • 红线memory 明文落盘，遵守 Z-09 不落凭据；涉密强度要求高时可整体关闭 auto memory（autoMemoryEnabled）。
  • 注记把 Z-08 之外"事实/偏好/纠偏往哪写"补成整套分层（Z-08 只覆盖纪要层）；已核实 memory 每会话只注入索引头、主题文件按需读。
  • 状态候选 · 在审 · 待批准入 Z-11。
候选

T-12 · 红线钩子化 · 机器把关拟定 → Z-12

  • 范围用户级 ~/.claude/settings.json 的 hooks ＋独立守卫脚本目录；先把 Z-09（凭据零明文）等最要命红线挂硬拦；密提交另叠 git pre-commit 双保险。
  • 机制PreToolUse 在权限检查前执行、能穿透 bypassPermissions，钩子只能收紧不能放松——把 Z-09 变成"写文件/密提交前扫描、命中即 deny"的机器闸。
  • fail-closed守卫脚本 catch 一切异常后按"拦"处理（钩子默认超时 60s、退出码非 2 即放行＝fail-open；误配成 exit 1 等于没拦，是最常见的坑）。
  • 双保险Claude 会话内动作由 Code hook 拦；含人手在内的所有提交由 git pre-commit 拦；两层叠用才是真强制。
  • 边界hook 是配置文件、会话内可被诱导改动，本质是"防线不是锁"；个人机要真锁靠系统只读 ACL 锁 settings/hook 文件（管理员可改）。不把 hook 当绝对安全。
  • 注记执行时先试点再放开，避免误拦卡日常；hook 配置变更纳入登记与复核。
  • 状态候选 · 在审 · 待批准入 Z-12。
候选

T-13 · 例行任务定时化 · 真无人值守拟定 → Z-13

  • 范围跨天/跨会话的例行动作（首推 外链巡检 周检）；机制＝Windows 任务计划程序 到点拉起无头 claude -p 执行。
  • 背景Claude 会话内定时/循环只在当前会话存活期有效、约 7 天自动过期——扛不起"每周固定必跑"；云 Routine 读不到本机 E:\。本机真定时只能走 OS 调度＋claude -p。
  • 无人值守默认只读优先（--permission-mode plan）；上限护栏（--max-turns / --max-budget-usd）防跑飞烧钱；stdout+stderr 落 过程记录（只增不改）；exit≠0 即告警。
  • 放宽条件需自动落纪要时才放宽：--permission-mode acceptEdits 且 --allowedTools 限定到 过程记录/**，不放全写。
  • 认证不用交互登录（OAuth 约每周过期、无头下不可靠）；任务环境用 setup-token / ANTHROPIC_API_KEY。出网 HTTPS_PROXY 与 git 的 http.proxy 是两回事，分别配。
  • 注记哪些任务上系统定时、频次，按本机实际分批启用并登记；全部动作可审计、可回滚。
  • 状态候选 · 在审 · 待批准入 Z-13。
