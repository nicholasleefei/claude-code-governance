T-16 · 先研后建 · 重大项目的启动纪律拟定 → Z-21 · 分类：流程纪律

  • 由来2026-11-04 会议拍板：新起「电商总工作台」不直接开工。理由：盲目开工 → 工作量翻倍 → 用户编程专业不足 → 反复造车；且以往项目技术栈与数据库都有问题，老资产不够专业，故新起项目；但存量资产须先体检、再分档纳入（另见 T-17）。
  • 结论新建大型项目（尤其跨多个既有系统的「总工作台」级项目）不得直接开工；先在 E:\my projects 立「启动前技术栈研究及测试」项目，研究期产出实施方案（含选型判据、禁则、里程碑），经用户逐条拍板定案后方可开工。
  • 门槛满足任一条即属「重大项目」，必须走研究期：涉及 ≥3 个既有项目；引入 ≥2 类新技术栈；涉及数据库选型。
  • 边界研究期不写生产代码、不上线、不改既有系统、不删存量资产；研究期长度建议 1–2 个月（上限 2 个月），续期须再拍板；研究产物不得直接进生产。
  • 关联Z-19（项目说明书）、Z-06（版本库）、Z-11（记忆分层 · 一事一层）、章程 P-6（逐条拍板 · 草案未批准不生效）、P-8 / P-9（书记长领衔并行书记团 · 多 Agent 拆分规则）。
  • 状态候选 · 在审 · 未生效（候选卡≠生效；入宪须用户逐条拍板）。

T-17 · 存量资产体检与分档纳入拟定 → Z-22 · 分类：资产治理

  • 由来2026-11-04 会议拍板：新起项目须先体检存量资产。本机存量约 147 件（31 项目 / 25 模型 / 51 skill / 2 MCP / 11 CLI / 27 工具），先体检、再分档纳入。
  • 结论任何「新起」项目启动前，须对本机存量资产（项目 / 模型 / skill / MCP / CLI / 工具）先做体检，结论落三档：直接复用 / 抽取公共件后复用 / 封存只读；未体检资产不得进入新系统的依赖树；判据先行、结论可验收。
  • 判据体检判据至少覆盖三维度——技术栈、数据（数据库）、工程；每维须有可操作的判定动作与通过线（如依赖可离线还原、数据库有迁移与回滚路径、密钥不入库、有最小可跑测试）。
  • 边界体检≠搬家；封存≠删除（Z-11 一事一层、Z-03 停用不删夹）；台账只记路径不记质量，故须开实体判定；与目标系统无关的资产可只登记不体检（体检范围由项目章程界定，本轮用户拍板为全量、分波执行）。
  • 关联Z-02 / Z-03 / Z-04 / Z-17（五仓登记制：01-model / 02-skill / 03-mcp / 04-cli / 05-tool）、Z-19（项目说明书）、Z-11（记忆分层 · 一事一层）。
  • 状态候选 · 在审 · 未生效（候选卡≠生效；入宪须用户逐条拍板）。
