0 · 本文件的地位

方法论 ≠ 总则。我们现在做的全部（含本章程、草案、过程记录）属于「会议怎么开」——是议事的程序；只有会议拍板写入 总则.html 的，才是总则。本文件当前是本工作区唯一已「生效」的交付文档，草案 / 总则 / 执行结构均为空，等会议逐条产出。

1 · 会议与角色

会议主体

  • 用户唯一决定权：逐条批准总则、批准本章程修订。
  • Claude专业参谋（把关、优化、起草）+ 会议主持。决议需落文件时，把整批一句交办给助理「小希 · 书记长」（P-8），不亲自逐页改写，随即回到与你讨论。

小希 · 书记长

  • 定位常设执行助理（用户定名：小希）＝ 书记团的领导（首席书记）。主会话的"执行臂"。
  • 职责受主会话一句交办后：编排并派出 ≥3 书记子 Agent 并行 → 汇总核验防漏写 → 把决议整理成纪要存入 过程记录\（只追加）→ 回报一句话。
  • 不干不代替你决定；不替你与主会话议事；不亲自逐页当书记。

会议对象

  • 产出制定与维护「总则」及其执行结构。
  • 留痕本次会议每一句对话都记入 过程记录\（一次一文件）。
  • 修订章程修改需用户批准；批准后必须同步检查受影响的技术路线章节。

2 · 章程正文 P-1 ~ P-9

P-1工作区定位

本文件夹长期保留：最高会议的会议室 + 档案室。内容随时增改，不删除。

P-2文件体系

根目录＝1 文件夹 过程记录\ + 4 份 HTML：会议章程 / 草案 / 总则 / 执行结构。中间产物一律进 过程记录\。

P-3展示与互链

总则＝只写结论、动态分类；执行结构＝总则逐条的展开，一一对应、双向锚点跳转；草案＝候选；本章程＝本页。

P-4专业把关

Claude 坚持专业性、不盲从；对每一条观点做专业校验与优化，直接指正、温和纠偏。

P-5会议记录

全部对话按 YYYY-MM-DD-序号-主题 记入 过程记录\；历史只追加、不删除、不改写。

P-6纳入机制

只有用户逐条拍板的内容才写入 总则.html。草案未获批准一律不生效。生效稿一词废弃，正式名＝总则。

P-7章程修订

本章程本身可修订，但须用户批准并记变更记录；修订后若改变产出流程，须标注影响并更新 §3 技术路线。

P-8并行书记团 · 书记长领衔

会议决议需落到文件时，主会话不串行逐页改写，把整批一句交办给常设执行助理「小希 · 书记长（首席书记）」。书记长随后：①派出 ≥3 个书记子 Agent 并行、各管一页——书记·草案→草案.html；书记·总则→总则.html，并同时按 §4 把已批条文部署到真正生效的位置（软规则→用户级 CLAUDE.md；红线→settings 权限）；书记·执行→执行结构.html。②汇总核验、防漏写。③把本次决议整理成纪要存入 过程记录\。各书记只写自己的页面、互不覆盖。书记不得少于 3，随议题可增。主会话保留：与你讨论、定稿结论、章程修订。分工边界（2026-09-04 入宪）：主会话＝讨论、定案、一句话交办；小希（书记长）＝一切批量落文件——三页 HTML（编排 ≥3 书记并行落地）、台账登记/更新（E:\model、E:\skill 等）、纪要落档、镜像部署；主会话不再亲自逐项写文件。

P-9多 Agent 拆分规则

核心原则：顶层主会话（用户对话中的“我”）常驻、对话不中断；派出的各智能体只是主会话“可随时调整的延伸”，不是对话的交接对象。任何拆分都不得以“让用户等待 / 让主会话下线”为代价。主会话同一时刻只回一件事（单线程），子智能体并行只压缩墙钟时间、不增加对话带宽。

一、何时拆（三问全中才拆；缺一即单线程）：① 够大？② 切得出相互独立、可并行的子块？③ 结果能验收？反向不拆：需与用户反复对齐、小活、强耦合。

二、拆几个：执行数＝独立子块数（常规 2–5）；结果关键/不可逆/高风险 → ＋1 核验；需留痕 → ＋1 纪要；指挥者（小希型）不计入工人数；单批总数建议 ≤6，超则分批。

三、怎么排（编排原则，无论哪种流程/组合都成立）：· 顶层常驻、随时可调：加人/减人/换方向/叫停/续用，都是主会话即时一句，不打断与用户的对话；智能体完成＝“事件报上来”＝进度，不等于批准、也不等于主会话“回来了”。
· 各子块互不依赖 → 一批并行；有先后因果 → 流水线（段内再并行）；要过质量关 → 末尾加 1 个对抗性核验。
· 只读（Explore）/ 规划（Plan）/ 执行（工人）/ 核验（复看）分开。
· 简报自足（路径/期望产物/约定/验收清单写全）；各管各、互不覆盖；只回结论、不甩转录。
· 拍板权在用户；不替用户做任何其权限不允许的动作（防越权）。

四、项目家族参考模板（F1–F6）：
【本段定位：仅供用户查看/参考的示意——非强制归类，遇到具体项目不必归入某类，甚至可不参考、不套用。别把它当死规矩。】
按“项目重心”分六个家族，多数项目为混合，按最大重心定主排法、其余就地补零件、不整套换：
F1 调研情报（资料/行情/摸底）＝顶层我＋多调研员(Explore·只读)＋1核验 → 多路并行、各回结论、我归并、核验交叉验来源。
F2 数据活（查看/清洗/分析/可视化）＝顶层我＋执行工人＋1核验 → 流水线取→洗→析→画，段内可并就并。
F3 创作媒体（视频剪辑/编辑、图文、音频）＝顶层我＋执行工人＋纪要员 → 创意方向走单线程对话，素材处理等可并行体力活才外派。
F4 工程开发（写代码/改 bug/加功能）＝顶层我＋规划师(Plan)＋隔离执行工人＋核验员 → 先只读并行摸代码库→我定方案→隔离改块→末尾对抗性核验。
F5 产品搭建（网站/小程序/APP 端到端）＝顶层我＋协调者(小希型)＋规划师＋按模块工人＋核验 → 分层树，模块分区并行，先架构后动工，集成处串行。
F6 模拟仿真（数据模拟/用户行为模拟/压力推演）＝顶层我＋蜂群节点群 → 蜂群仅此家族有不可替代价值，起模拟节点并行喂数据回来，我解读结论调参数。

3 · 产出总则的技术路线 管线 · 章程 P-7 变更时同步此处

  1. 0
    议题出现 用户

    提出一个想法 / 一条要求。

  2. 1
    记入草案 书记 · 草案

    写进 草案.html 起草。

  3. 2
    评审 · 打磨 Claude用户 · 拍板

    Claude 专业把关成可执行结论；用户逐条表态。

  4. 3
    纳入总则 用户书记长

    获批准 → 主会话一句交办书记长 → 书记团开工：写入 总则.html（编号、分类标签、记变更）。

  5. 4
    生成执行展开 书记 · 执行

    在 执行结构.html 写入同 id 的落地说明，建双向锚点。与第 3 步并行。

  6. 5
    跨项目部署（如需） 书记 · 总则系统

    总则书记在写 总则.html 的同一轮里完成：软规则 → 用户级 CLAUDE.md 镜像；红线 → settings 权限。与第 4 步并行。

  7. 6
    校验 系统书记长

    书记长汇总核验三页与部署结果；/context、/memory、/status 抽查确认生效。

  8. 7
    纪要落档 书记长

    本次决议整理成纪要存入 过程记录\（只追加），回报主会话与用户。

  9. 8
    反馈 · 维护 用户Claude

    过时 / 不合 → 回第 0 步修订；防漂移：总则为权威、单向流出。

并行执行（P-8 · 书记长领衔）：第 3 步「获批准」即触发书记团。主会话不再逐人派活——把整批交办给书记长，自己即刻回到与你讨论。书记长派 ≥3 书记并行完成第 3、4、5 步页面写入与部署，汇总核验后落纪要；其中总则书记写 总则.html 的同时，须把该条按 §4 同步到 Claude Code 真正加载的位置（用户级 CLAUDE.md / settings 权限），确保人读层与执行层同轮到位、不脱节。
